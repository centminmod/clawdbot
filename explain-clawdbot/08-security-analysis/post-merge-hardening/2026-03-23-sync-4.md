#### Exec Approval Boundary Hardening — strictInlineEval ([`a94ec3b79`](https://github.com/openclaw/openclaw/commit/a94ec3b79b))

A new `strictInlineEval` configuration flag blocks interpreter inline-eval forms (`python -c`, `node -e`, `ruby -e`, `osascript -e`) from reusing existing interpreter allowlist patterns. The new module `src/infra/exec-inline-eval.ts` provides `detectInterpreterInlineEvalArgv()` (detects inline-eval forms in argv) and `describeInterpreterInlineEval()` (generates human-readable descriptions for approval prompts). The exec approval flow in `src/agents/bash-tools.exec.ts` passes `strictInlineEval` from config to downstream validation, and the same gate is applied in `invoke-system-run` and `node-host` execution paths.

Additionally, `extensions/discord/src/monitor/inbound-context.ts` now wraps untrusted Discord message bodies via `wrapExternalContent()` from `src/security/external-content.ts`, marking message content as untrusted before it reaches agent context. This reduces the risk of prompt injection or env-variable-style injection from adversarial Discord messages. Audit warnings are added for autoAllowSkills and interpreter allowlists configured without strictInlineEval.

#### Safe-Bin Semantic Validation — jq Audit Warning ([`0ac939059`](https://github.com/openclaw/openclaw/commit/0ac939059e))

A new module `src/infra/exec-safe-bin-semantics.ts` extracts safe-bin semantic validation (jq env filter detection) from the main exec-approvals path. `validateSafeBinSemantics()` checks whether the resolved safe-bin binary exhibits broad behaviors (such as jq's ability to read environment variables via `env` filter), and `normalizeSafeBinName()` canonicalizes binary names for consistent policy lookup. For broad-behavior bins, the runtime raises a `tools.exec.safe_bins_broad_behavior` audit finding (`src/security/audit.ts:1176`), surfacing the configuration risk to operators rather than silently trusting the bin.

#### Minimum Host Version Enforcement ([`3ce5a8366`](https://github.com/openclaw/openclaw/commit/3ce5a8366a))

New module `src/plugins/min-host-version.ts` implements `checkMinHostVersion()`, which validates that the gateway's current host version satisfies the `openclaw.install.minHostVersion` semver floor declared in a plugin or skill manifest. A companion `src/plugins/manifest-registry.ts` centralizes manifest version field lookups. The check runs at install time in `src/plugins/install.ts`, blocking plugins and skills whose declared minimum version exceeds the gateway version. All extension `package.json` files were updated to declare their minimum host version, raising the baseline compatibility bar and providing defense-in-depth against installing packages that assume host capabilities not present in older releases.

#### ClawHub Archive Install Hardening ([`04b283ffc`](https://github.com/openclaw/openclaw/commit/04b283ffc2))

`resolvePackedRootDir()` in `src/infra/archive.ts` gains a `rootMarkers` parameter, allowing the archive root detection to search for custom marker files (`SKILL.md`, `openclaw.plugin.json`) in addition to the previously hardcoded `package.json` and bundle-root layouts. The parameter propagates through the withExtractedArchiveRoot() and installPluginFromArchive() call stacks in `src/infra/install-flow.ts`. This prevents archive installs from failing silently on non-standard directory layouts and eliminates a category of silent fallback to an unvalidated root.

#### Native ClawHub Install Flows ([`91b280024`](https://github.com/openclaw/openclaw/commit/91b2800241))

New `installSkillFromClawHub()` in `src/agents/skills-clawhub.ts` (line 236) adds native skill installation directly from ClawHub, including a gateway-side skill install endpoint and CLI integration in `skills-cli.ts` and `plugins-cli.ts`. The new install surface relies on the minimum host version enforcement introduced in `3ce5a8366a` for compatibility gating. The outPath arbitrary write gap (Audit 2 Claim 2) applies to `nodes:screen_record`, not the ClawHub archive install path, which routes through `resolvePackedRootDir()` in `src/infra/archive.ts`.
