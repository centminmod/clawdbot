### #10646: Weak UUID Generation Fallback to Math.random() (HIGH)

**CWE:** CWE-338 (Use of Cryptographically Weak PRNG)
**Filed by:** jascal (2026-02-06, automated scan)

**Upstream claim:** `ui/src/ui/uuid.ts:27` falls back to `Math.random()` when Web Crypto API is unavailable.

**Local validation:** CONFIRMED AFFECTED at multiple locations.

1. **`ui/src/ui/uuid.ts:23-33`** — `weakRandomBytes()` function:
   - Uses `Math.floor(Math.random() * 256)` in a loop to fill 16 bytes
   - XORs with `Date.now()` (first 4 bytes only) — adds minimal entropy
   - Called from `generateUUID()` at :55-56 when `crypto.randomUUID` AND `crypto.getRandomValues` are both unavailable
   - **Risk:** LOW in practice — modern browsers and Node.js always have Web Crypto. Would only trigger in very restricted/old environments. A console warning IS emitted.

2. **`src/auto-reply/reply/get-reply-inline-actions.ts:191`** — toolCallId generation:
   - `const toolCallId = cmd_${Date.now()}_${Math.random().toString(16).slice(2)}`
   - **Always** uses Math.random() — no crypto fallback path
   - Used as correlation ID for tool call/result pairing in session transcripts
   - **Risk:** MEDIUM — predictable IDs in the tool call protocol. An attacker with access to the session could predict future IDs. Collision risk is low but non-zero.

3. **Secondary findings (LOW risk):**
   - `src/cron/store.ts:52` — tmp file suffix (PID + Math.random)
   - `src/cron/run-log.ts:38` — tmp file suffix (PID + Math.random)
   - `src/browser/trash.ts:16` — trash file suffix
   - `src/tts/tts.ts:380` — tmp audio file suffix

4. **Non-security uses (cosmetic/UI):**
   - `src/agents/session-slug.ts:104,141` — human-readable session names
   - `src/auto-reply/reply/reply-dispatcher.ts:38` — typing delay jitter
   - `src/infra/backoff.ts:12`, `src/infra/retry.ts:66` — retry jitter
   - `src/tui/tui.ts:426`, `src/cli/tagline.ts:265` — random display phrases

**Crypto usage confirmed:** 52 files use `crypto.randomUUID` or `randomBytes`, confirming proper crypto IS used for most security-sensitive paths.

### #7139: Default Config Zero Isolation / Plaintext Credentials (MEDIUM)

**CWE:** CWE-276 (Incorrect Default Permissions)
**Filed by:** joshyorko

**Upstream claim:** Default configuration provides zero sandbox isolation and stores credentials in plaintext.

**Local validation:** PARTIALLY AFFECTED — claims are a mix of valid concerns and already-mitigated defaults.

1. **Sandbox defaults to "off":** CONFIRMED.
   - `src/agents/sandbox/config.ts:147` — `mode: agentSandbox?.mode ?? agent?.mode ?? "off"`
   - A Docker sandbox with proper isolation exists but is opt-in only
   - **Impact:** Agents can access the full host filesystem by default

2. **Gateway binds to loopback by default:** MITIGATED.
   - `src/cli/gateway-cli/run.ts:177` — `cfg.gateway?.bind ?? "loopback"`
   - Non-loopback bind modes require authentication (enforced at :249)
   - **Overstated:** The claim of "zero isolation" ignores loopback binding

3. **Plaintext credentials:** CONFIRMED (known/documented).
   - Credentials stored in `~/.openclaw/credentials/` with 0o600 permissions
   - `collectSecretsInConfigFindings()` at `audit-extra.ts:147-175` flags plaintext passwords
   - `redactConfigSnapshot()` mitigates exposure in config dumps (PR #9858)
   - File permission hardening is extensive: 80+ locations use 0o600/0o700

4. **No CORS protection:** Not validated (gateway-specific, depends on bind mode).

**Overall assessment:** The sandbox-off-by-default is the primary valid concern. The plaintext credentials issue is standard for CLI tools and already has audit warnings and file permission hardening.

### #9875: Race Condition — Orphaned tool_use Blocks (MEDIUM)

**CWE:** CWE-362 (Concurrent Execution Using Shared Resource with Improper Synchronization)
**Filed by:** mikecourt

**Upstream claim:** Backgrounded exec jobs create tool_use blocks that outlive session persistence, leading to orphaned blocks and synthetic error injection.

**Local validation:** CONFIRMED AFFECTED.

1. **`src/agents/session-transcript-repair.ts:166-318`** — `repairToolUseResultPairing()`:
   - Handles orphaned tool_use by inserting synthetic error tool_results (:290-296)
   - Moves displaced tool results back to correct position (:280-283)
   - Drops duplicates (:183-186) and orphaned tool_results (:208-211)
   - Skips aborted/errored assistant messages (:224-227) to avoid API 400s

2. **Callers** (via LSP incomingCalls):
   - `sanitizeToolUseResultPairing()` at :154 (convenience wrapper)
   - `pruneHistoryForContextShare()` at `src/agents/compaction.ts:343`

3. **Gap:** The repair is **reactive only** — runs at context-build time, not at session-persist time.
   - No flush-before-persist hook
   - Repairs are never written back to session files
   - Tool-result guard state is in-memory only, lost on restart

**Impact:** Workflows with long-running backgrounded exec jobs (builds, encoding, etc.) will accumulate orphaned tool_use blocks. The repair prevents API rejections but adds noise via synthetic error results.
